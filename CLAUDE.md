# Kubick Launcher — заметки для работы над проектом

Лаунчер Minecraft на Electron. Основное описание — в [README.md](README.md),
здесь только то, что нужно знать перед правками, и грабли, на которые уже наступали.

## Устройство

Три слоя, между ними нет прямых связей:

- `src/main/` — вся работа с системой и сетью. Каждый файл отвечает за одно:
  `mc/` (версии, установка, запуск), `mods/`, `modpacks.js`, `java.js`, `lan.js`,
  `friends.js`, `vpn.js`, `themes.js`, `fonts.js`, `instance-data.js`, `updater.js`.
- `src/preload.js` — единственный мост. Renderer видит ровно то, что здесь перечислено;
  `contextIsolation: true`, `nodeIntegration: false`.
- `src/renderer/` — интерфейс без сборщика: обычные `<script>`, без npm-пакетов и JSX.
  Правки видны сразу, шага сборки нет.

Все IPC-обработчики обёрнуты в `handle()` (`src/main/index.js`): ошибка возвращается
в интерфейс понятным текстом, а не «Error invoking remote method».

## Проверка изменений

Быстрая проверка синтаксиса всего проекта:

```bash
for f in $(find src tools -name "*.js"); do node --check "$f" || echo "FAIL $f"; done
```

Модули главного процесса проверяются обычным `node -e` с подменой корня данных:

```bash
KUBICK_LAUNCHER_ROOT=/tmp/test node -e "require('./src/main/mods/index.js')"
```

Модули, которым нужен Electron (`instance-data.js` использует `nativeImage`),
запускаются через `./node_modules/.bin/electron script.js`.

Интерфейс удобно проверять статикой: поднять локальный сервер на `src/renderer`,
подменив `window.api` заглушкой, и читать DOM. Полезно ещё до сборки.

## Грабли, которые уже стоили времени

**Нативные библиотеки.** В манифесте Mojang у `natives-windows`, `natives-windows-x86`
и `natives-windows-arm64` одинаковые `rules` — архитектура закодирована в имени
классификатора. Если полагаться только на правила, распаковываются все три и 32-битная
`lwjgl.dll` затирает 64-битную. Отбор делает `nativeFitsHost()` в `mc/rules.js`.

**Флаги JVM.** `G1NewSizePercent` и `G1MaxNewSizePercent` — экспериментальные опции,
без `-XX:+UnlockExperimentalVMOptions` перед ними JVM вообще не стартует. Набор
в `store.js` проверен запуском на Java 17 и 25; перед правкой прогоняйте `java <флаги> -version`.

**Пути со сборками.** Имя папки сборки транслитерируется в латиницу (`instances.js`):
кириллица в пути ломает часть модов с нативными библиотеками.

**Smart App Control (Windows 11).** Блокирует неподписанные приложения полностью,
не предупреждая. Мешает и сборке: NSIS на последнем шаге запускает свежесозданный
деинсталлятор и падает с `spawn UNKNOWN`. Настоящее решение — подпись кода,
временное — собирать в CI.

**Черновики релизов.** electron-builder по умолчанию публикует релиз черновиком,
а electron-updater черновики не видит. В `build.publish` обязателен
`"releaseType": "release"`, иначе обновления молча не приходят.

**Блокировка единственного экземпляра.** Запущенная установленная версия перехватывает
запуск из исходников: процесс молча завершается с кодом 0. Поэтому в dev-режиме
`userData` отдельный (`index.js`). Если приложение «ничего не делает» — проверьте,
не запущена ли вторая копия.

## Выпуск версии

Поднять `version` в `package.json`, затем:

```bash
git add -A && git commit -m "Версия X.Y.Z" && git push
```

```bash
git tag vX.Y.Z && git push origin vX.Y.Z
```

GitHub Actions соберёт установщик и опубликует релиз с `latest.yml`.
Версия в теге и в `package.json` должны совпадать.

## Что не проверено вживую

- Вход через Microsoft — нужен реальный аккаунт и Azure Client ID.
- Каталог CurseForge и его сборки — нужен API-ключ.
- Само VPN-подключение: список серверов и генерация `.ovpn` проверены,
  а поднятие туннеля меняет маршруты системы и требует прав администратора.

Остальное проверялось запуском: ваниль, Fabric, Forge и NeoForge доходят до игры,
модпаки ставятся целиком, друзья находятся в сети, обновление скачивается и применяется.
