# Kubick Launcher

Десктопный лаунчер Minecraft на Electron: сборки с модами, автоматическая установка Java,
вход через Microsoft и встроенный каталог модов Modrinth + CurseForge.

## Возможности

**Окно и удобство**
- Окно подстраивается под размер экрана и запоминает, каким его оставили
- Меню игрока над карточкой аккаунта: папка, аккаунт, выход
- Каталог модов открывается прямо в окне сборки, отобранное копится в корзине
  и скачивается разом — с галочками, что именно ставить

**Окно сборки**
- Слева разделы: Журнал, Версия, Моды, Наборы ресурсов и шейдеров, Заметки, Миры,
  Серверы, Снимки экрана, Параметры, Другие журналы
- Данные читаются из настоящих файлов игры: названия и версии модов — из jar,
  миры — из level.dat, наборы — из pack.mcmeta, серверы опрашиваются по протоколу Minecraft
- Библиотека сборок — плотный список, как каталог модов

**Игра и сборки**
- Все версии Minecraft из официального манифеста Mojang, включая снапшоты
- Загрузчики модов: **Fabric**, **Quilt**, **Forge**, **NeoForge** — устанавливаются в один клик
- Forge и NeoForge ставятся из официальных установщиков с выполнением процессоров
  (деобфускация и патчинг клиента), как в оригинальном инсталляторе
- Изолированные сборки: у каждой свои моды, конфиги, миры и ресурспаки
- Дублирование сборки, переустановка повреждённых файлов, отдельный лимит памяти на сборку

**Java**
- Автоматически находит Java в системе (Adoptium, Corretto, Zulu, Semeru, Microsoft, JAVA_HOME,
  рантайм официального лаунчера)
- Если подходящей версии нет — сам скачивает нужный Temurin с Adoptium под версию игры
- Ручной выбор пути к `java.exe` в настройках

**Аккаунты**
- Вход через Microsoft по коду устройства: пароль вводится только на сайте Microsoft
- Полная цепочка Xbox Live → XSTS → Minecraft Services с понятными сообщениями об ошибках
- Автоматическое продление сессии по refresh-токену
- Офлайн-аккаунты с UUID, вычисленным так же, как на ванильном сервере

**Готовые сборки игроков**
- Выбираются прямо при создании сборки — вкладка «Готовая сборка игроков»
- **Modrinth** (.mrpack) и **CurseForge**; рядом с каждой видно, под какие версии Minecraft она собрана
- Лаунчер сам ставит нужную версию игры, загрузчик и все моды, копирует настройки автора

**Друзья**
- Обменялись кодами один раз — дальше мир, открытый другом, **сам** появляется
  в списке серверов Minecraft, вводить адрес не нужно
- Список друзей с их открытыми мирами; серверы сборок в том же разделе
- Ручное добавление адреса для игры через интернет

**Серверы**
- Подборка популярных публичных серверов: логотип, адрес, задержка и живой онлайн
- Данные опрашиваются у самих серверов по протоколу Minecraft, ничего не выдумано
- У каждого сервера отмечено, нужна ли лицензионная учётная запись Minecraft
- Подключение одним нажатием: адрес пишется в сборку, игра стартует сразу на сервере

**Перенос сборок**
- Экспорт сборки в один файл `.kubick` с выбором, что вложить: моды, конфиги,
  наборы ресурсов и шейдеров, настройки игры, миры
- Видно размер каждой части до сохранения — миры обычно весят больше всего остального
- Импорт показывает содержимое файла до установки; версия игры и загрузчик
  скачиваются заново, поэтому файл остаётся небольшим

**VPN**
- Бесплатные серверы открытого проекта **VPN Gate** (университет Цукубы) с выбором страны
- Список стран со сводкой: сколько серверов, лучший пинг, максимальная скорость
- Подключение через OpenVPN либо сохранение готового .ovpn для своего клиента
- Системный VPN меняет маршруты всей машины, поэтому его поднимает клиент OpenVPN
  с правами администратора; если нужен другой адрес только для игры — раздел «Смена IP»

**Смена IP**
- Свои SOCKS5-прокси: проверка на живость показывает, какой адрес видит внешний мир
- Подключения к серверам, которые начинает лаунчер, идут через выбранный прокси
- Прав администратора и установки драйверов не требует
- Работает так: игра соединяется с локальным портом лаунчера, а тот тянет соединение
  через прокси — сервер видит адрес прокси. SRV-запись сервера при этом читается за игру
- Границы честные: сервер, вписанный руками внутри игры, пойдёт напрямую;
  системный трафик и другие программы это не затрагивает

**Внешний вид**
- Темы фона: космос, гонки, природа, PvP, PvE. Картинки скачиваются из свободных источников —
  медиатека NASA (общественное достояние) и Wikimedia Commons с фильтром по public domain и CC0
- Палитра взята из вашего портфолио: тёплый графит, песок, шалфей, терракота
- Своё фото или гифка на фон, с регулируемым затемнением и выключаемой анимацией
- Открытые шрифты с кириллицей (Inter, Onest, Manrope, Rubik, JetBrains Mono и другие)
  скачиваются по требованию; San Francisco подхватывается системный на macOS
- Настройки разложены по страницам, есть сброс к заводским
- Четыре стиля кнопок окна: macOS, Windows, скруглённые, штрихи
- Сворачивание в трей при закрытии — включается в настройках
- У каждой сборки свои настройки Java, памяти и окна, поверх общих
- Пять акцентных цветов, окно в стиле macOS
- Браузер версий Minecraft с переключением между списком и карточками

**Каталог модов**
- **Modrinth** — работает сразу, без ключей
- **CurseForge** — нужен бесплатный API-ключ
- Поиск модов, ресурспаков и шейдеров; фильтры по категории, версии игры и загрузчику
- Ограничение по версии сборки снимается одной кнопкой — под свежие версии Minecraft
  выходит далеко не всё, и без этого выдача выглядит почти пустой
- Выдача листается кнопкой «Показать ещё», рядом видно, сколько показано из скольких
- Каждый тип живёт отдельно: моды, наборы ресурсов и шейдеры не смешиваются
  ни в выдаче, ни в корзине
- Автоматическая установка обязательных зависимостей
- Управление установленными файлами: включение/выключение и удаление

**Надёжность**
- Проверка SHA1 у каждого скачанного файла; битые файлы перекачиваются
- Загрузка во временный файл с атомарным переименованием — недокачанное не попадает в кеш
- Ретраи с экспоненциальной задержкой, параллельная очередь загрузок
- Диагностика падений: нехватка памяти, несовместимая Java, драйверы GPU, конфликты модов
- Работа со списком версий из кеша при отсутствии сети
- Токены доступа вырезаются из логов

## Требования

**Windows 10 или новее, 64 бита.** Планку задаёт Electron: начиная с версии 23
он собран на Chromium 110, а тот не запускается на Windows 7, 8 и 8.1. Сейчас
в проекте Electron 33 — это Chromium 130 и Node 20.18, и обе половины требуют
Windows 10. Последняя ветка Electron с поддержкой Windows 7 — 22.x, её выпуски
прекратились в октябре 2023 года.

Установщик проверяет версию системы до распаковки и объясняет отказ, вместо того
чтобы установиться и молча не запуститься. Ту же проверку делает и сам лаунчер —
она нужна портативной сборке, которая ставится мимо установщика.

Minecraft и Java лаунчер скачивает сам, отдельно ставить их не нужно.

## Установка

Скачайте `Kubick-Launcher-Setup-1.6.2.exe` и запустите — обычный установщик:
выбор папки, ярлыки на рабочем столе и в меню «Пуск», запись в «Установка и удаление программ».
Права администратора не нужны: установка идёт в профиль пользователя.

Есть и портативная сборка `Kubick-Launcher-1.6.2-portable.exe` — один файл, запускается без установки.

> **Неподписанная сборка.** Windows встретит её двумя разными способами:
>
> - **SmartScreen** покажет синее окно «Windows защитила ваш компьютер» —
>   нажмите «Подробнее» → «Выполнить в любом случае»;
> - **Smart App Control** (Windows 11) не предупреждает, а полностью блокирует запуск.
>   На стороне пользователя это не обходится — помогает только подпись кода.
>
> Эта же политика мешает и сборке: NSIS на последнем шаге запускает свежесозданный
> деинсталлятор, и сборка падает с ошибкой `spawn UNKNOWN`. Собирайте установщик в CI
> или на машине без Smart App Control. Подробнее — в разделе «Подпись кода».

### Что происходит при удалении

Удаление через «Параметры → Приложения» убирает саму программу и ярлыки.
**Сборки, миры, моды и настройки остаются** — они лежат в `%APPDATA%\.kubick-launcher`,
отдельно от программы. Чтобы стереть и их, удалите эту папку вручную.

## Сборка из исходников

```bash
npm install
```

Запуск в режиме разработки:

```bash
npm start
```

Сборка установщика и портативной версии в папку `dist/`:

```bash
npm run dist
```

Пересоздать иконку из фирменного знака:

```bash
npm run icon
```

> **Если сборка падает на `Cannot create symbolic link`** — это известная особенность
> electron-builder на Windows: в его архиве для подписи лежат macOS-симлинки, а их создание
> требует прав, которых нет у обычного пользователя. Включите «Режим разработчика»
> в параметрах Windows либо распакуйте архив вручную без macOS-части:
>
> ```bash
> node_modules/7zip-bin/win/x64/7za.exe x -y "-o$LOCALAPPDATA/electron-builder/Cache/winCodeSign/winCodeSign-2.6.0" "$LOCALAPPDATA/electron-builder/Cache/winCodeSign/"*.7z "-x!darwin"
> ```

## Автообновление

Обновления берутся из **GitHub Releases**. Нужно заполнить одно поле —
`repository` в `package.json`:

```json
"repository": "https://github.com/Hlracigmny/kubick-launcher"
```

Этот же адрес использует electron-builder при публикации, поэтому приложение и сборка
не могут разъехаться. Репозиторий уже указан, проверка обновлений включена.

В `build.publish` стоит `"releaseType": "release"`. Без него electron-builder кладёт релиз
в черновики, а electron-updater черновики не видит — обновления бы просто не приходили.

### Как выпустить версию

Через GitHub Actions (рекомендуется — сборка идёт на чистой машине):

```bash
git tag v1.5.1 && git push origin v1.5.1
```

Workflow [`.github/workflows/release.yml`](.github/workflows/release.yml) соберёт установщик
и выложит его в Releases вместе с `latest.yml`. Токен Actions выдаёт сам, заводить ничего не нужно.

Либо вручную со своей машины — понадобится персональный токен GitHub с правом `repo`:

```bash
GH_TOKEN=ваш_токен npm run release
```

Главное — поднять `version` в `package.json` перед выпуском: именно по нему установленные
лаунчеры понимают, что вышла новая версия.

### Как это выглядит у пользователя

Через 8 секунд после запуска лаунчер тихо проверяет обновления. Если версия новее —
показывает уведомление и кнопку «Скачать» в разделе Настройки; без спроса ничего не качается.
Загруженное обновление ставится при следующем перезапуске.

В портативной сборке и при `npm start` проверка отключена — там обновлять нечего.

### Как проверить канал обновлений до публикации

Проверку можно включить и в режиме разработки, подменив источник переменными окружения —
пересобирать приложение не нужно:

```bash
KUBICK_UPDATE_DEV=1 KUBICK_UPDATE_FEED=http://localhost:7393/ KUBICK_UPDATE_AUTODOWNLOAD=1 npm start
```

Ход проверки пишется в `%APPDATA%\.kubick-launcher\logs\updater.log`: у оконного приложения
на Windows нет консоли, и без этого журнала причину молчания обновлений не найти.
Рабочая последовательность выглядит так:

```
источник: {"provider":"generic","url":"http://localhost:7393/"}, текущая версия 1.1.0
checking
available 1.2.0
downloading 1.2.0
ready 1.2.0
```

## Подпись кода

Без сертификата Windows будет показывать предупреждение SmartScreen. Если сертификат есть,
укажите его через переменные окружения перед сборкой — electron-builder подхватит их сам:

```bash
CSC_LINK=/путь/к/certificate.pfx CSC_KEY_PASSWORD=пароль npm run dist
```

## Настройка входа через Microsoft

Mojang выдаёт доступ к API входа по заявке, поэтому лаунчер использует ваш собственный
идентификатор приложения Azure (бесплатно):

1. [portal.azure.com](https://portal.azure.com) → **Azure Active Directory** → **App registrations** → **New registration**
2. Тип поддерживаемых аккаунтов: **Personal Microsoft accounts only**
3. Раздел **Authentication** → включить **Allow public client flows**
4. Скопировать **Application (client) ID** и вставить в **Настройки → Интеграции → Azure Client ID**

Без этого работают офлайн-аккаунты — их достаточно для одиночной игры
и серверов с `online-mode=false`.

## Игра по сети с друзьями

**Один раз:** откройте вкладку **Игра по сети**, скопируйте свой код (вида `KB-A1B2-C3D4`)
и обменяйтесь им с другом. Каждый добавляет другого — этого достаточно навсегда.

**Каждый раз:** хозяин мира заходит в игру и нажимает `Esc` → **Открыть для сети** →
**Открыть мир для сети**. У всех друзей его сервер **сам** прописывается в список серверов
Minecraft — они просто заходят в «Сетевую игру» и видят его там.

### Как это устроено

Minecraft, открывая мир, объявляет о нём в локальную сеть, но в его сообщении нет имени
игрока — только описание мира и порт. Поэтому лаунчер шлёт рядом собственный маленький
пакет со своим кодом и ником. Лаунчер друга ловит его, сверяет код со списком друзей
и записывает адрес в `servers.dat` нужных сборок.

Из этого следует два момента:

- Сервер появляется в игре **при следующем запуске** — файл со списком серверов
  Minecraft читает один раз, на старте.
- Чужие люди ваш мир так не увидят: пакеты с неизвестными кодами игнорируются.

### Через интернет

Механизм рассчитан на одну сеть. Чтобы играть с друзьями из других городов, поднимите
общий VPN — **Radmin VPN**, **ZeroTier** или **Hamachi**. Для лаунчера это обычная локальная
сеть, и всё описанное продолжает работать без каких-либо настроек.

Альтернатива без VPN — проброс порта на роутере у хозяина мира; тогда друзья добавляют
его адрес вручную кнопкой «Добавить по адресу».

## Ключ CurseForge

Каталог Modrinth работает без настройки. Для CurseForge получите бесплатный ключ на
[console.curseforge.com](https://console.curseforge.com) и вставьте его
в **Настройки → Интеграции**.

## Где лежат файлы

```
%APPDATA%\.kubick-launcher\
├── versions/     версии Minecraft и профили загрузчиков
├── libraries/    библиотеки (общие для всех сборок)
├── assets/       ресурсы игры (общие)
├── java/         скачанные рантаймы Java
├── fonts/        скачанные шрифты интерфейса
├── backgrounds/  своё изображение для фона
├── friends.json  список друзей
├── instances/    сборки: моды, конфиги, миры
├── logs/         логи запусков
└── settings.json настройки, аккаунты, список сборок
```

Библиотеки и ассеты общие для всех сборок, поэтому десять сборок на одной версии
не занимают в десять раз больше места.

## Структура проекта

```
src/
├── main/                  главный процесс Electron
│   ├── index.js           окно и все IPC-обработчики
│   ├── paths.js           расположение данных
│   ├── store.js           настройки, аккаунты, сборки (атомарная запись)
│   ├── net.js             загрузки: ретраи, SHA1, очередь параллелизма
│   ├── java.js            поиск и установка Java
│   ├── instances.js       жизненный цикл сборок
│   ├── modpacks.js        установка сборок с Modrinth и CurseForge
│   ├── lan.js             поиск миров в сети и список серверов сборки
│   ├── nbt.js             чтение и запись servers.dat
│   ├── fonts.js           каталог и загрузка открытых шрифтов
│   ├── instance-data.js   чтение модов, миров, наборов и журналов сборки
│   ├── mcping.js          опрос серверов Minecraft (пинг, MOTD, игроки)
│   ├── servers.js         подборка публичных серверов и их живое состояние
│   ├── instance-io.js     экспорт и импорт сборок файлом .kubick
│   ├── proxy.js           смена IP: клиент SOCKS5 и локальный ретранслятор
│   ├── vpn.js             серверы VPN Gate и запуск OpenVPN
│   ├── themes.js          картинки тем из NASA и Wikimedia
│   ├── friends.js         друзья и автоподстановка их серверов
│   ├── backgrounds.js     своё изображение для фона
│   ├── updater.js         автообновление (выключено, включается одной строкой)
│   ├── auth/accounts.js   Microsoft OAuth и офлайн-аккаунты
│   ├── mods/index.js      Modrinth и CurseForge
│   └── mc/
│       ├── manifest.js    манифест версий Mojang
│       ├── rules.js       правила ОС, аргументы, maven-пути
│       ├── install.js     установка версии: jar, библиотеки, нативы, ассеты
│       ├── launch.js      сборка команды JVM и запуск процесса
│       └── loaders/       fabric.js (Fabric + Quilt), forge.js (Forge + NeoForge)
├── preload.js             мост в renderer через contextBridge
└── renderer/              интерфейс (без сборщика — обычные скрипты)
```

Renderer работает с `contextIsolation: true` и без `nodeIntegration`: доступ к системе
только через явный список методов в `preload.js`.
