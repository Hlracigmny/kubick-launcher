# MongoDB для сервера аккаунтов

Пошагово: от пустого места до работающей базы. Занимает минут пятнадцать,
платить не нужно — бесплатного тарифа хватает с большим запасом.

Если база нужна только чтобы посмотреть, как работает вход, — её можно вообще
не заводить. Запущенный без `KUBICK_MONGO_URL` сервер держит данные в памяти:
для проверки этого достаточно, но при перезапуске всё пропадает.

---

## 1. Завести кластер в Atlas

Atlas — облачная MongoDB от самих разработчиков базы. Своя установка тоже
подойдёт, про неё в конце.

1. Зарегистрируйтесь на [mongodb.com/cloud/atlas/register](https://www.mongodb.com/cloud/atlas/register).
   Карта не нужна.
2. Создайте кластер, выбрав тариф **M0** — он бесплатный и бессрочный.
3. Регион берите ближайший к тому месту, где будет крутиться сам сервер аккаунтов,
   а не к вам: между ними будет ходить каждый запрос.
4. Имя кластера любое, менять его потом нельзя.

Что даёт M0: 512 МБ данных и общий процессор. Для ориентира — одна учётная
запись занимает меньше килобайта, так что упереться в потолок можно примерно
на полумиллионе игроков. Ограничение, до которого дойдёте раньше, — общий
процессор: при заметной нагрузке кластер начнёт подтормаживать, и это повод
перейти на платный тариф, а не признак поломки.

## 2. Создать пользователя базы

**Database Access → Add New Database User.**

- Способ входа: Password.
- Имя: например `kubick`.
- Пароль: нажмите **Autogenerate Secure Password** и сразу скопируйте — второй раз
  его не покажут.
- Права: **Read and write to any database**.

> Это учётная запись *базы*, а не вашего аккаунта Atlas. Путать их — обычное дело,
> и попытка войти паролем от Atlas даёт ошибку «authentication failed».

**Если пароль придумываете сами** — избегайте символов `@ : / ? # %` или будьте
готовы закодировать их. Пароль живёт внутри URL, и `@` там означает «дальше адрес
сервера». Пароль `p@ss` превращает строку подключения в мусор. Закодировать можно так:

```bash
node -e "console.log(encodeURIComponent('ваш пароль'))"
```

## 3. Разрешить доступ по адресу

**Network Access → Add IP Address.**

Atlas по умолчанию не пускает никого. Добавьте IP машины, где будет работать
сервер аккаунтов.

- Для проверки со своего компьютера — кнопка **Add Current IP Address**.
- Для развёрнутого сервера — его внешний IP.

Про `0.0.0.0/0` («разрешить отовсюду»). Так делают, когда хостинг не даёт
постоянного IP, и во многих инструкциях это предлагают как норму. Это не норма:
единственным барьером остаётся пароль базы. Если без этого никак — считайте пароль
базы таким же секретом, как ключ подписи токенов, и меняйте его при любом подозрении.
Лучше всё же выяснить у хостинга диапазон исходящих адресов и вписать его.

## 4. Взять строку подключения

**Database → Connect → Drivers**, версия Node.js 6.x или новее. Строка выглядит так:

```
mongodb+srv://kubick:ПАРОЛЬ@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority
```

Подставьте свой пароль вместо `ПАРОЛЬ`.

**Тут прячется главная ловушка.** В этой строке нет имени базы: между `.net/`
и `?` пусто. Драйвер в таком случае молча берёт базу `test`, и данные оказываются
не там, где вы будете их искать. Допишите имя:

```
mongodb+srv://kubick:ПАРОЛЬ@cluster0.abcde.mongodb.net/kubick?retryWrites=true&w=majority
```

Либо задайте отдельной переменной `KUBICK_MONGO_DB=kubick` — сервер поймёт оба
варианта. Если ни того, ни другого нет, при старте будет предупреждение про `test`.

## 5. Запустить сервер

```bash
cd server && npm install
```

В этом проекте `argon2` уже собран и проверен — в логе будет `пароли: argon2id`.
Если на другой машине его сборка не пройдёт, это не страшно: он объявлен
необязательным, сервер переключится на scrypt из стандартной библиотеки и скажет
об этом в логе. Пароли остаются защищёнными, а когда argon2 всё же установится,
база перехешируется сама при следующих входах.

Ключ подписи токенов создайте один раз и храните как пароль:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Запуск:

```bash
KUBICK_MONGO_URL="mongodb+srv://kubick:ПАРОЛЬ@cluster0.abcde.mongodb.net/kubick" KUBICK_JWT_SECRET="ваш-ключ" npm start
```

Признак, что всё сошлось:

```
[store] MongoDB подключена, база: kubick
Kubick Account на порту 8787 (хранилище: mongodb, пароли: argon2id)
```

Если написано `хранилище: memory` — переменная не долетела до процесса,
и данные пишутся в память.

### Переменные

| Переменная | Обязательна | Что делает |
|---|---|---|
| `KUBICK_MONGO_URL` | для настоящей базы | строка подключения; без неё — память |
| `KUBICK_MONGO_DB` | нет | имя базы, если его нет в строке |
| `KUBICK_JWT_SECRET` | да в продакшене | ключ подписи токенов |
| `PORT` | нет | порт, по умолчанию 8787 |
| `NODE_ENV` | нет | `production` запрещает старт без `KUBICK_JWT_SECRET` |

## 6. Проверить

```bash
curl http://localhost:8787/v1/health
```

Ответ `{"ok":true,"storage":"mongodb","passwords":"argon2id"}` означает, что база
на месте. Дальше — полный прогон, он заведёт тестового пользователя:

```bash
cd server && npm test
```

Тест работает на памяти и вашу базу не трогает. Чтобы убедиться, что пишется
именно в Mongo, зарегистрируйте кого-нибудь вручную:

```bash
curl -X POST http://localhost:8787/v1/register -H "Content-Type: application/json" -d "{\"username\":\"TestPlayer\",\"password\":\"проверочный-пароль\"}"
```

И посмотрите в Atlas: **Browse Collections → kubick → users**. Там будет запись,
в которой `passwordHash` — нечитаемая строка, а не пароль. Так и должно быть.

Коллекции и индексы сервер создаёт сам при первом подключении, руками ничего
готовить не нужно.

### Проверить базу одной командой

```bash
cd server && KUBICK_MONGO_URL="ваша-строка" npm run check-db
```

Он отвечает на то, что иначе проверяют глазами в интерфейсе Atlas: подключились ли,
в какую базу легли данные (и не в `test` ли), создались ли **уникальные** индексы —
без них два игрока способны занять один ник, — и как выглядит сохранённый пароль.
Ничего не меняет, только читает.

Пример вывода на настроенной базе:

```
       база: kubick
       коллекции: users, friends
       учётных записей: 1
       занято данными: 0.01 МБ из 512 МБ на M0
  OK   подключение к MongoDB
  OK   база названа осмысленно
  OK   индекс users.usernameLower
  OK   индекс friends.from+to
  OK   пароли захешированы
```

## 7. Прописать адрес в лаунчере

**Настройки → Интеграции → Сервер аккаунтов Kubick.** Туда идёт адрес сервера
целиком, например `https://account.example.com` (или `http://localhost:8787`,
пока проверяете локально). После этого раздел «Аккаунты» оживёт.

Наружу сервер должен смотреть по HTTPS: через него ходят пароли. Обычно это
делается обратным прокси (nginx, Caddy) с сертификатом Let's Encrypt перед
сервисом на локальном порту.

## Если что-то не работает

Сервер переводит три самые частые ошибки Atlas на человеческий, так что
сообщение при старте скорее всего сразу скажет, куда смотреть.

| Что видно | В чём дело |
|---|---|
| «отклонила логин или пароль» | Пароль **пользователя базы**, а не аккаунта Atlas. Проверьте, не нужно ли закодировать спецсимволы |
| «не пускает с этого адреса» | Network Access: IP не в списке. У домашнего интернета он ещё и меняется |
| «не удалось разрешить адрес кластера» | Опечатка в строке или у сервера нет DNS. `mongodb+srv` требует SRV-записей — часть корпоративных сетей их режет |
| `хранилище: memory` | Переменная не дошла до процесса. В systemd её задают через `Environment=`, а не в shell |
| предупреждение про базу `test` | В строке нет имени базы — допишите `/kubick` |

## Резервные копии

Одна из причин, по которой выбрана обычная MongoDB, — данные всегда можно забрать:

```bash
mongodump --uri="mongodb+srv://kubick:ПАРОЛЬ@cluster0.abcde.mongodb.net/kubick" --out=backup
```

Восстановление:

```bash
mongorestore --uri="mongodb+srv://kubick:ПАРОЛЬ@cluster0.abcde.mongodb.net/kubick" backup/kubick
```

На M0 автоматических копий нет — это отличие бесплатного тарифа, о котором стоит
помнить. Регулярный `mongodump` по расписанию закрывает вопрос.

## Своя MongoDB вместо Atlas

Всё написанное работает и с локальной базой, меняется только строка подключения:

```
mongodb://kubick:ПАРОЛЬ@localhost:27017/kubick?authSource=admin
```

Схема `mongodb://` вместо `mongodb+srv://` — без SRV-записей. Два условия:
версия MongoDB 5.0 или новее и включённая авторизация (`--auth`). База без пароля,
доступная из сети, находится ботами за часы.
